# 개발 노트 — RL3D

만들면서 **무엇이 어떻게 깨졌고 어떻게 알아냈는지**의 기록이다. 기능 소개가 아니라
**판단 기록**이라 *"이건 아직 안 쟀다"* 도 그대로 적는다. 각 노트 끝의 **근거** 에서
커밋과 실행 가능한 명령을 확인할 수 있다.

"아무것도 안 보인다"** 쪽으로 몰렸다.

## 두 편인 이유

후보를 캐는 단계에서 **34건**이 나왔다. 한 편을 지탱할 서사가 이어지는 것이 둘이라
둘만 썼다 — 전부와 **왜 안 골랐는지**는 [`CANDIDATES.md`](CANDIDATES.md) 에 있다.

**다음 순번으로 올려 둔 것 둘:**

1. **측정이 계획을 뒤집었다** — 로드맵에 "렌더 성능이 문제일 것"이라 적어 둔 항목을
   착수 전에 재 보니 **전제부터 틀렸다**(갱신은 매 프레임이 아니라 초당 1회, 8,000개도
   28ms). 측정 30분으로 구현이 불필요해졌고, 그 측정이 대신 **캡 상향이라는 실제
   개선**을 찾아냈다. 그리고 **Node 단독 벤치는 5,000개 86ms 로 더 느리게 나온다** —
   그 수치를 믿었으면 반대 결론이 났다
2. **픽스처에 남의 연락처가 올라가 있었다** — 유튜브 설명문이 통째로 들어가
   채널 운영자의 SNS·사업용 이메일이 공개 저장소에 있었다. **파싱에 쓰이지도 않는
   필드**라 지워도 골든이 안 바뀌었고, **생성 스크립트도 같이 고쳤다** — 안 고치면
   다음 픽스처 갱신에 그대로 돌아온다
